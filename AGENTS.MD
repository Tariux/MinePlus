Mineplus is a Spigot/Paper plugin focused on a data-driven "vanilla-like systems" framework: custom items, managed blocks, multiblocks/machines, recipes, GUIs, and virtual rendered models, all server-side (no client mod required).

Runtime starts in `MineplusPlugin`: it loads `settings.mp.yml` via `ConfigManager`, applies `VirtualRenderingSettings` to `VirtualBlockManager`, loads model assets from the plugin data folder, then bootstraps `PluginContext`. `PluginContext` wires `ItemRegistry` and the infrastructure engine + `InfrastructureApi`.

The modern extension core is `InfrastructureEngine`. It composes:
- `MultiBlockRegistry` (type registry + instance indices by UUID/location)
- `MultiBlockLifecycleManager` (create/place/interact/upgrade/remove/tick, model reload, save/restore)
- `ModelRenderingManager` (maps multiblock level -> virtual model spawn/swap/remove through `VirtualBlockManager`)
- `MultiBlockLinkingSystem` + `HookBus` (block links, signals, lifecycle event fanout)
- `RecipeManager`, `UpgradeManager`, `InfrastructureGuiManager`, and persistence/config loaders.

Feature definitions can come from code or JSON:
- Code: use `InfrastructureApi` (`registerMultiBlock`, `create/place/upgrade/remove`, `registerHook`, lifecycle listeners, recipe/gui registration, linking/signals).
- JSON multiblocks: `plugins/Mineplus/multiblocks/*.json` parsed by `MultiBlockConfigLoader` into `MultiBlockType` + `MultiBlockLevel` (`model`, `speed`, `durability`, `upgradeCost`, `guiOptions`, optional `gui` key).
- JSON machine recipes: `plugins/Mineplus/recipes/*.json` parsed by `RecipeConfigLoader` into `MachineRecipe`.

Virtual rendering pipeline (`infrastructure.virtual`):
- `BbModelImporter` single-pass streaming parser (Gson `JsonReader`): `.bbmodel` -> `VirtualModel`. Dead branches (texture `source` Base64 PNGs, animations, timeline setups) are skipped with `skipValue()` and never allocated. Captures `resolution` and per-element `light_emission`; preserves negative-coordinate geometry and outliner pivot-conjugation transforms.
- Anchor convention (`ORIGIN_MODE`, default `CENTER`): vanilla/Blockbench space — pixel (0,0,0) is the anchor block's center at its base (a full block spans pixels [-8..8] xz, [0..16] y). Single-block models occupy exactly one block and rotate about the block center. `GRID` (corner anchor) is available for multi-block structures; `LEGACY` is an alias of `CENTER`.
- `RotationSnapper` snaps placement rotations to the 24 orientation-preserving signed axis permutations, giving exact integer voxel-lattice transforms; deviations beyond the threshold are warned via `DebugLogger`.
- `VoxelOccupancyCalculator` geometry-aware collision: per-cube SAT voxelization (axis-aligned fast path), `GEOMETRY` (default) / `SURFACE` (interior hollowing) / `AABB` (legacy fill) modes, packed long cell set, per-(model, orientation, mode) cache. Voxelization consumes the exact same `T(anchorOffset)·R·M` transform the displays use, so barriers and visuals cannot drift.
- `TextureMaterialResolver` filename->vanilla-material pipeline (curated map -> direct match -> suffix-strip -> aliases -> fuzzy -> fallback) with a JVM-lifetime cache; unresolved names are reported per model (`/mineplus model info`).
- `DisplayEmitter` per-cube emission: fast path = one `BlockDisplay` per uniform cube; mixed-material cubes add thin per-face plates (box mapping parity, UV in-plane rotation, `light_emission` -> brightness).
- UV alignment layer: `FaceUvAnalyzer` inspects each `BakedFace` UV window (sub-region, half, wrap, flip, rotation) and `OrientableBlockStates` renders it — half-texture windows via slab-type crops with geometry compensation; wrapping windows via native-density tile grids (one display per texture tile, no stretching); directional materials get `facing`/`axis` block states so fronts/rings/lines land on the referencing face; full windows render the complete texture. `/mineplus model info` reports per-face UV diagnostics; arbitrary sub-pixel crops need a client resource pack and are out of scope.
- `ModelMeta` per-model overrides via `models/<key>.meta.json` (`textureMode`, `originMode`, `collisionMode`, `autoplay`).
- Animation engine (`infrastructure.virtual.animation`): `BbModelImporter` parses `animations` in the same streaming pass (clips, bone animators keyed by outliner group name, molang-tolerant keyframes; splines sampled linear, effect animators skipped). `VirtualModel` carries the preorder bone graph (outliner groups, parent indices, pivots) + clips; `BakedCube.boneIndex` binds cubes to their innermost group. `AnimationEvaluator` samples tracks (clamped lerp/step) and composes hierarchical delta matrices `world[bone] = world[parent]·T(p/16)·R(Δr)·S(Δs)·T(-p/16)·T(Δt/16)` (Rz·Ry·Rx Blockbench Euler order, additive per-channel clip blending). `ModelAnimationManager` ticks controllers off `VirtualBlockManager.activeBlocksView()` — spawns self-attach, removals self-clean, autoplay (level `animations` key > meta `autoplay`) fires once per rendered id and never overrides explicit control. Displays get `T(pivotFix)·R·boneDelta(t)·restLocal` via `setTransformationMatrix` with client-side `setInterpolationDuration`, so motion renders at the client frame rate (the server cannot push faster than its tick loop; `TICK_INTERVAL_TICKS: 1` is the max-rate default). Selector API: `AnimationApi` (`playAnimation/stopAnimation/pauseAnimation/resumeAnimation/triggerAnimation/setAnimationEnabled/getAnimations/getBones/getAnimationState`) with `AnimationSelector.animation/bone/all`; `MultiBlockHook.onAnimationStart/onAnimationComplete` fire through the isolated bridge implemented by `MultiBlockLifecycleManager`. `ONCE` clips remove controllers and return to rest; `HOLD` freezes the end frame; paused/completed controllers push no packets.
- `VirtualBlockManager` spawn/remove, barrier placement, spawn-area policy (`prepareSpawnArea`: creative/op placements clear non-air occupants; standard players require an empty area and get an "insufficient space" message via `MultiBlockLifecycleManager.place`), ghost `BlockDisplay` cleanup on chunk loads. `ModelRenderingManager` resolves per-level model paths and binds rendered model IDs back to instances.

Configuration and logging:
- `ConfigManager` auto-generates `plugins/Mineplus/settings.mp.yml` on first start; the `VIRTUAL_RENDERING` section controls collision mode/epsilon/non-air policy, rotation snapping, per-face rendering, texture mode, and origin mode. The `ANIMATION` section controls the animation runtime (`ENABLED`, `TICK_INTERVAL_TICKS` default 1, `INTERPOLATION_TICKS`, `AUTOPLAY`). `UPDATE_CHECKER.RESOURCE_ID` (default `0` = off) gates an optional SpigotMC version check (`util/UpdateChecker`) that runs once on enable, async.
- bStats metrics are always enabled (plugin id 33702) via the vendored bStats sources relocated to `com.mineplus.bstats` in `src/main/java/com/mineplus/bstats` (bstats-bukkit 3.2.1, MIT, vendored from Maven Central sources jars; relocation is required — `MetricsBase.checkRelocation` refuses to start under the original `org.bstats` package; opt-out lives in `plugins/bStats/config.yml`). `libs/` stub jars are committed so external builds and CI work.
- `DebugLogger` gates all additional lifecycle, rendering, persistence, and linking logs behind `ADDITIONAL_DEBUG_LOGS` (default `false`). When disabled, only essential plugin lifecycle logs are emitted.
- `/mineplus model info <key>` reports cube count, display estimate, resolved texture table, occupancy cells with ASCII layer dumps, and cache status.

Current architecture direction is stabilization/alignment of the infrastructure layer; prefer extending via `InfrastructureApi` + engine managers instead of ad-hoc listeners.

Module layer (features live outside the Core): `examples/mineplus-fun` is the canonical reference module — a separate plugin (`depend: [Mineplus]`) containing the Juicer (recipes/GUI/custom items), the Cannon (conditional interaction: torch fires, else opens menu; persistent TNT ammo in `stateData`; rotation-aware placement via `createMultiBlock`/`placeMultiBlock`), and the Gear (redstone-driven bbmodel clip animation with chain reaction through `AnimationApi`). Module internals follow the `ModuleFeature` lifecycle contract: features implement `id()`/`onEnable()`/optional `onDisable()`+`command()`; the bootstrap starts all features (exception-isolated per feature), performs exactly one coordinated `reloadAll()` for the whole module, then registers the features' commands; teardown runs in reverse enable order. Its `DEVELOPMENT_PROMPT.md` is the authoritative module-building recipe (verified Core behavior, GUI patterns, API traps). Keep the Core pristine: no feature code, no feature resources, no feature commands.

User documentation lives in `docs/` (`README.md` hub, `config-reference.md`, `developer-api.md`, `extension-workflows.md`) with assets in `docs/assets/`; the root `README.md` is the GitHub presentation. Keep these in sync when behavior changes.
